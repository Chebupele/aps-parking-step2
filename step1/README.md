# Бизнес-домен и маппинг

## Мониторинг занятости парковок

Камеры передают кадры в сервис, который определяет количество свободных парковочных мест и обновляет табло. Число обработчиков ограничено, поэтому поступающие кадры могут ожидать в общем буфере.

Для табло важна актуальность данных. При заполнении буфера новый кадр занимает место самого старого ожидающего кадра. На обслуживание выбирается последняя поступившая заявка.

## Элементы СМО

| Элемент | Объект бизнес-домена | Класс |
|---|---|---|
| Источник (ИБ, ИЗ2) | Камера с модулем отправки кадров | CameraSource |
| Заявка | Задание на анализ одного кадра | FrameRequest |
| Буфер | Общая память на M ожидающих кадров | FrameBuffer |
| Диспетчер постановки (Д1ОЗ1, Д1ОО3) | Программный модуль приёма кадров | IntakeDispatcher |
| Диспетчер выбора (Д2П2, Д2Б2) | Программный планировщик обработки | ServiceDispatcher |
| Прибор (ПЗ1) | Рабочий процесс анализа одного кадра | FrameProcessor |
| Получатель результата | Табло занятости парковки | — |

Каждая камера независимо генерирует заявки с равномерно распределёнными интервалами. Один обработчик выполняет одно задание; длительность обслуживания имеет экспоненциальное распределение.

Оба диспетчера — программные алгоритмы. Диспетчер постановки принимает кадр, ищет место в буфере по кольцу и при переполнении удаляет самую старую заявку. Диспетчер выбора извлекает самый новый кадр и назначает его свободному обработчику, найденному по кольцу.

В имитационной модели распознавание кадра заменяется случайной длительностью обслуживания. Исследуются время ожидания, отказы и загрузка обработчиков.
